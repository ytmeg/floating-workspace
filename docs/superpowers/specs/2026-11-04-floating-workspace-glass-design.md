# 悬浮工作台玻璃视觉设计

- 日期：2026-11-04
- 状态：视觉方向、图标、实现结构和验收均已由用户确认
- 项目：悬浮工作台
- 范围：第一阶段完成后的视觉优化，不增加第二阶段或第三阶段功能

## 1. 目标与边界

在保持现有布局、编辑行为、快捷键、持久化和窗口恢复不变的前提下，优化应用图标、窗口玻璃材质、模式图标和明暗模式。

- 浅色模式采用用户选择的 C「浅色渐变玻璃」。
- 深色模式采用用户选择的 B「深色 HUD 玻璃」。
- 应用图标采用用户选择的 C「悬浮徽章」。
- 自动跟随系统明暗外观，首版不增加手动主题开关。
- 不修改便签字号、左侧模式栏结构、全局快捷键或数据格式。
- 图片和网页仍为禁用入口，不提前实现后续功能。

## 2. 视觉规范

### 2.1 浅色 C

- 背景由浅蓝 `#E0F4FF` 和浅紫 `#EEE4FF` 组成渐变。
- 两个颜色停止点分别使用约 0.68 和 0.60 的 alpha，最终视觉同时受桌面背景和系统材质影响。
- 使用柔和浅色边框、顶部内侧高光和低强度阴影。
- 选中态以蓝紫色和半透明浅色底组成，不依赖颜色单独表达状态。

### 2.2 深色 B

- 背景以深蓝黑 `#121926` 为主，alpha 约 0.64。
- 使用浅色低强度边框和阴影，避免纯黑实心窗口。
- 图钉、选中态和焦点强调色使用浅蓝 `#8BD0FF`。
- 正文和控件使用动态高对比文字颜色，不通过降低文字透明度制造玻璃感。

### 2.3 内容层级

- 窗口背景和左侧模式栏保留最明显的玻璃效果。
- 便签正文、输入框、按钮和保存状态使用更清晰的内容底色，保证可读性。
- 窗口圆角与图标圆角保持统一，不为每个控件重复添加阴影和边框。
- 空白模式继续以用户选择的背景色为主，蓝紫渐变和玻璃材质不得覆盖用户颜色；切回便签时恢复材质和主题渐变。
- 现有最小窗口尺寸、16pt 便签字号和控件点击区域不缩小。

## 3. 图标系统

### 3.1 应用图标

采用「悬浮徽章」概念：叠放的半透明窗口形体与一个小图钉徽章，表达浮动窗口和置顶。

- 使用自行绘制的可编辑矢量原稿，不复制 Apple 或第三方图标。
- 提供浅色和深色两套颜色资源，由系统外观选择。
- 生成 macOS 所需多尺寸图标，确保小尺寸下仍能辨认主体。
- 接入 `.app` 资源打包和图标元数据。

### 3.2 菜单栏与模式图标

- 菜单栏使用单色模板图，由 macOS 自动适配明暗。
- 标题栏置顶状态继续使用清晰的 SF Symbols，并与菜单勾选状态同步。
- 便签、图片、网页、空白使用一致的线性图标风格，保留中文标签，不用纯图标取代文字。
- 图片和网页禁用状态仍通过禁用控件表达，不利用新图标暗示功能已可用。

## 4. 实现结构

### WorkspaceAppearance

集中管理颜色、alpha、边框、选中态和实色回退，避免各控制器分别硬编码。窗口阴影使用 `NSPanel.hasShadow` 原生能力，不在内容背景 layer 上添加自定义阴影。根据当前有效外观和辅助功能设置返回动态值。

### GlassBackgroundView

使用公开 `NSVisualEffectView` 构建背景，叠加浅色模式的蓝紫渐变层。背景位于所有编辑控件后方，不拦截鼠标和键盘输入，不改变现有控制器的业务逻辑。空白模式的用户颜色由面板背景绘制，玻璃层保持透明，避免半透明颜色叠加两次。

1pt 边框由最上层、不拦截事件的 `GlassBorderView` 绘制：只描左、右、下三边，下方两角使用与 titled panel 遮罩一致的圆角，顶边由系统标题栏分隔线承担。

控制器在有效外观变化和 `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification` 时无条件刷新 palette；内容变化只有在模式或空白背景色改变时才刷新，便签逐键输入、置顶、标题和保存状态不触发重新着色或渐变重绘。

### 图标资源与打包

保留可编辑矢量原稿和生成的资源。资源包括浅色／深色 App Icon、单色菜单栏模板图和模式图标。构建脚本负责校验资源并打包进 `.app`，缺少必要资源时构建失败并指出文件名。

### 可访问性与性能

- 系统开启「减少透明度」时使用对应的实色背景，不显示透明玻璃。
- 系统开启「增强对比度」时加强边框和文字对比。
- 外观切换由 AppKit 通知驱动，不创建轮询计时器。
- 不添加持续动画、高频重绘或背景模糊计时器。

## 5. 回退与错误处理

- 图标资源缺失或格式错误时，构建脚本明确失败，不生成无图标的伪完成包。
- 无法应用系统材质时，回退到对应实色背景，不影响编辑和置顶。
- 外观切换失败不得影响已保存内容、窗口 frame 或置顶状态。
- 用户背景色无法解析时，沿用现有数据校验和错误处理，不新增静默重置。

## 6. 验证策略

### 自动化测试

- 保留现有 52 项测试。
- 补充浅色／深色主题解析、减少透明度回退、资源完整性和禁用模式状态测试。
- 验证标题栏图钉、菜单勾选和实际 `isPinned` 状态一致。
- 验证视觉切换不会触发额外保存或修改持久化内容。

### 视觉与真机验收

1. 浅色 C 和深色 B 在浅色、深色桌面背景下都清晰可读。
2. 系统切换明暗模式时，窗口和图标无需重启即可更新。
3. 菜单栏小图标、Dock 图标和模式图标在小尺寸下仍能辨认。
4. 「减少透明度」显示实色回退；「增强对比度」边界更清楚。
5. 便签正文、空白模式用户颜色、保存状态和警告框不被材质遮挡。
6. 最终签名包重新通过八组功能验收，无置顶、编辑、保存或窗口恢复回归。
7. 检查无持续动画、额外高频重绘和新增特殊权限。

## 7. 完成标准

只有资源打包、自动化测试、明暗视觉检查、辅助功能回退和八组功能验收全部通过，才可声明视觉优化完成。不得把图片、网页或后续编辑能力纳入本次完成声明。
