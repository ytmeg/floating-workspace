- 工作名：悬浮工作台

## 1. 背景与方向调整

2026-10-30 的「置顶任意第三方 App 窗口」方案未通过真实 WindowServer 排序验收。实验表明，在 SIP 开启且不注入其他进程的约束下，非窗口所有者调用私有层级接口不能证明真实 z-order 已改变。用户决定停止该方案，改为只置顶应用自己创建的窗口，不再使用 SkyLight。

新产品是一个可编辑、可本地保存内容的悬浮工作台。四种内容模式分阶段交付，第一阶段只实现便签和空白模式。

## 2. 总体产品边界

- 使用公开 AppKit；不修改 SIP，不注入 Dock 或其他 App。
- 不读取或修改第三方 App 的窗口层级。
- 不申请辅助功能或屏幕录制权限。
- 内容和设置只保存在本机，不做账号或遥测。第一阶段不联网；第三阶段仅允许用户主动加载网页所需的网络请求。
- 项目以 MIT 许可证准备；GitHub 公开和推送仍需单独取得用户确认。

### 分阶段范围

**第一阶段，本设计文档的实现范围**

- 一个始终可置顶的自有浮窗。
- 左侧模式栏、便签纯文本编辑、空白演示窗。
- 全局快捷键、菜单栏入口、自动保存和启动恢复。

**第二阶段，单独设计和计划**

- 图片导入、替换、删除、缩放和裁剪。
- 画笔、文字和箭头标注。

**第三阶段，单独设计和计划**

- 使用 WebKit 显示网页并编辑 URL。
- 在本地编辑网页正文，按 URL 保存修改，重新打开时尝试重放。
- 修改不写回远程网站；页面结构升级可能导致保存的修改无法继续重放。

## 3. 第一阶段用户体验

### 3.1 布局

采用用户已选择的「左侧模式栏」布局：

- 标题栏显示应用名「悬浮工作台」和当前置顶状态。
- 左侧固定显示便签、图片、网页、空白四个入口。
- 第一阶段便签和空白可用；图片、网页以禁用状态显示，不响应内容切换。
- 右侧为当前模式编辑区。
- 底部显示自动保存状态和全局快捷键提示。

默认窗口约 `520 × 540` pt，最小尺寸 `360 × 320` pt。便签默认字号为 16 pt，不通过缩小字体或控件来压缩布局。

### 3.2 浮窗与置顶

- 使用 `NSPanel`，`isFloatingPanel = true`。
- `hidesOnDeactivate = false`，切到其他 App 时不自动隐藏。
- 置顶时设置公开 `NSWindow.Level.floating`；取消后恢复 `.normal`。
- 点击标题栏图钉或按 `⌃⌥⌘P` 切换置顶。
- 浮窗仍可获得键盘焦点用于编辑；焦点离开后只保持显示，不抢占焦点。
- 第一阶段只保证在当前 Space 的普通窗口上方显示，不承诺跨 Space、全屏空间或系统面板之上的行为。

### 3.3 便签模式

- 使用可编辑 `NSTextView`，只保存纯文本，不做富文本或 Markdown 渲染。
- 用户停止输入约 300ms 后自动保存。
- 保存期间不阻塞输入；失败时保留编辑内容和 dirty 状态。
- 底部状态区分「保存中」「已保存」「保存失败」。

### 3.4 空白模式

- 显示一个可自定义的空白演示窗口。
- 可编辑窗口标题、背景色和当前窗口宽高。空白模式下，标题栏中央显示用户标题；切回便签模式后恢复应用名「悬浮工作台」。
- 宽高修改作用于真实浮窗，随后由 AppKit 保存窗口 frame。
- 标题和背景色写入本地内容模型。

### 3.5 菜单栏与快捷键

- App 使用 accessory 模式，不出现在 Dock。
- 菜单栏提供：显示／隐藏浮窗、切换置顶、退出。
- 全局快捷键固定为 `⌃⌥⌘P`，通过 Carbon 热键接口注册，不需要辅助功能权限。
- 快捷键注册失败时显示数字错误码，菜单栏操作仍可使用。
- 正常退出前将尚未保存的编辑内容落盘。保存失败时暂停退出并提示；用户可重试，或明确选择「放弃未保存内容并退出」。

## 4. 组件设计

### FloatingWindowController

负责 `NSPanel` 创建、置顶层级、显示／隐藏、窗口 frame 恢复和标题栏状态。窗口 frame 使用固定 autosave name `FloatingWorkspaceFrame` 由 AppKit 保存。

### WorkspaceViewController

负责左侧模式栏、便签编辑、空白设置和底部状态。图片与网页只呈现禁用入口，第一阶段不创建图片编辑器或 WebView。

### ContentStore

负责 Codable 内容模型、加载、300ms 防抖保存、原子写入、退出前 flush 和错误报告。存储行为通过协议注入，业务测试使用内存实现。

### HotkeyController

负责 Carbon 全局热键注册、注销和冲突错误。只发送切换置顶动作，不直接修改窗口。

### MenuBarController

负责菜单栏图标和菜单动作，复用同一个 `FloatingWindowController`，不另建第二份窗口状态。

## 5. 数据模型与持久化

存储位置：Application Support 下的 `FloatingWorkspace/workspace-v1.json`。

第一阶段模型：

- `schemaVersion`：固定整数 `1`。
- `selectedMode`：`note` 或 `blank`。
- `noteText`：完整便签纯文本，允许空字符串。
- `blankTitle`：空白模式标题，允许空字符串。
- `blankBackground`：保存 sRGB 的 red、green、blue、alpha 四个 0–1 浮点值。
- `isPinned`：布尔值，默认 `true`。

窗口尺寸和位置不重复写入 JSON，由 AppKit frame autosave 统一恢复。空白模式的宽高控件修改当前 frame，不建立第二套尺寸来源。

### 写入规则

- 编辑变化后防抖 300ms。
- 使用临时文件加原子替换，避免半写入 JSON。
- 写入失败保留 dirty 状态、当前编辑内容和可见错误；后续编辑或正常退出时重试。
- 启动遇到损坏 JSON 时，先把原文件移动为同目录 `workspace-v1.corrupt-<timestamp>.json`，再使用默认内容并显示恢复提示。不得直接覆盖唯一损坏原件。
- 第一阶段不提供多设备同步、版本历史或撤销持久化。

## 6. 错误处理

- **热键冲突**：提示数字错误码，保留菜单栏置顶操作。
- **保存失败**：底部持续显示失败，内容不丢，允许后续重试。
- **数据损坏**：保留带时间戳的原始副本，提示后进入默认状态。
- **窗口恢复失败**：使用默认尺寸和屏幕可见区域，不阻止编辑。
- **退出时仍有未保存内容**：先尝试 flush；失败则暂停退出，提供「重试」和「放弃未保存内容并退出」两个明确选择，不显示「已保存」。
- **图片或网页入口**：第一阶段只显示未启用，不返回假内容或成功状态。

## 7. 验证策略

### 自动化测试

- 模型默认值、模式切换和 Codable 往返。
- 便签保存防抖及连续编辑只保存最终值。
- 原子写入失败后 dirty 和内容保留。
- 损坏 JSON 被保留为带时间戳的副本。
- 置顶状态恢复和菜单／快捷键共用同一状态。
- 图片与网页模式在第一阶段不可选。

### 真机验收

1. 编辑便签后切到 Safari、备忘录和已安装 IDE，浮窗仍位于普通窗口上方。
2. 点击其他 App 时浮窗不抢回焦点；重新点击浮窗可继续编辑。
3. 按 `⌃⌥⌘P` 或菜单取消置顶后，浮窗恢复正常层级；再次操作恢复 `.floating`。
4. 修改空白窗标题、背景色和宽高，重启后全部恢复。
5. 便签内容、上次模式、窗口位置和置顶状态重启后恢复。
6. 隐藏浮窗后可通过菜单栏重新显示。
7. 模拟热键冲突、保存失败和损坏 JSON，三种提示及恢复路径符合本设计。
8. 全程无 Dock 图标、无辅助功能或屏幕录制权限请求、无网络请求。

## 8. 第一阶段完成标准

只有在自动化测试和全部真机验收通过后，才能声明第一阶段完成。图片编辑、网页正文编辑和网页修改重放不属于第一阶段完成声明；它们分别需要后续设计、计划和独立验收。
