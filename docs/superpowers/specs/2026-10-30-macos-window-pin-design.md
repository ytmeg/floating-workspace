# macOS 任意窗口置顶工具设计

- 日期：2026-10-30
- 状态：交互与技术方向已由用户确认
- 工作名：窗口置顶
- 本地仓库：`/Users/moni/AIWorkSpace/macos-window-pin`

## 1. 目标

做一个原生 macOS 菜单栏 App，把任意普通 App 的现有窗口置顶。窗口置顶后，即使用户把鼠标和键盘焦点切到其他 App，该窗口仍位于普通窗口上方。

首版供用户本机使用，并计划以 MIT 许可证开源到 GitHub。项目不进入 App Store。

## 2. 已确认的使用方式

- App 驻留菜单栏，不占用 Dock。
- 用户先切换到目标窗口，再按全局快捷键 `⌃⌥⌘P` 将其置顶。
- 对已经置顶的窗口再次按同一快捷键，取消置顶并恢复原窗口层级。
- 菜单栏弹层展示当前窗口、置顶窗口数量和已置顶窗口列表。
- 支持同时置顶多个普通窗口；所有置顶窗口高于普通窗口，但不保证置顶窗口彼此之间永远保持固定顺序。
- 用户可单独取消一个窗口，也可选择「取消全部置顶」。
- 正常退出 App 前，恢复本进程置顶且仍然存在的所有窗口。

交互设计稿已包含并确认三种状态：未置顶、已置顶、权限不足。

## 3. 首版范围

### 包含

- 任意第三方 App 的标准窗口。
- 全局快捷键置顶和取消。
- 菜单栏状态与置顶数量。
- 多窗口置顶、单独取消、全部取消。
- 辅助功能权限检查、设置入口和重新检查。
- 窗口关闭后的状态清理。
- 当前 macOS 系统上的私有接口可行性验证与真实窗口验收。

### 不包含

- App Store 发布。
- 注入其他 App、修改 SIP、安装系统扩展或后台守护进程。
- 截图浮窗、画中画或其他替代真正窗口层级的方案。
- 读取窗口正文、屏幕录制、联网、账号、遥测或分析上报。
- 系统受保护窗口、菜单栏、Dock、桌面和全屏窗口的置顶。
- 异常退出后的跨进程恢复；正常退出必须恢复，异常退出的限制写入 README。
- 窗口位置、尺寸、跨 Space 移动等窗口管理功能。

## 4. 技术方案

### 4.1 技术栈

- Swift。
- AppKit，负责菜单栏 App、弹层和窗口状态展示。
- macOS 全局热键接口，负责注册和处理 `⌃⌥⌘P`。
- Accessibility API，负责检查权限、取得当前 App 和当前标准窗口。
- 系统私有窗口接口，负责把窗口标识映射到系统窗口，以及读取、设置和恢复窗口层级。

SkyLight 属于 Apple 自带的私有系统框架，不是公开 SDK。App 只动态解析并调用本机已有接口，不复制或分发 Apple 的框架、私有源码和私有头文件。

### 4.2 模块边界

**MenuBarController**

负责菜单栏图标、弹层、三种界面状态和用户操作。只读取 View State，不直接调用系统私有接口。

**WindowPinService**

负责置顶、取消、全部取消、正常退出恢复，以及已关闭窗口的清理。只有系统调用成功后才把窗口标记为已置顶；失败时保留原状态并返回错误。

**HotkeyController**

负责全局快捷键注册、冲突报错和事件转发。快捷键始终作用于当前焦点窗口，不自行维护窗口业务状态。

**SystemWindowGateway**

隔离 Accessibility、窗口标识映射和私有 SkyLight 调用。向上一层提供「取得当前窗口」「读取层级」「设置层级」「恢复层级」四个能力。私有符号动态解析失败时返回明确的 `unsupported`，不导致 App 启动崩溃。

**PermissionController**

负责辅助功能权限状态、打开系统设置和重新检查。权限不足时不尝试置顶。

测试中使用假的 `SystemWindowGateway` 验证业务状态，不在单元测试中依赖真实第三方窗口。

## 5. 核心数据流

### 置顶

1. 用户按快捷键或点击「置顶当前窗口」。
2. App 检查辅助功能权限。
3. Gateway 取得当前焦点 App 的标准窗口及唯一窗口标识。
4. App 排除不支持的窗口类型，并记录该窗口原始层级。
5. Gateway 调用私有接口提高窗口层级。
6. 调用成功后加入置顶集合，菜单栏数量加一；调用失败则显示原因，不加入集合。

### 取消

1. 用户对当前窗口、列表中的某个窗口或全部窗口执行取消。
2. Gateway 恢复已记录的原始层级。
3. 恢复成功后从置顶集合移除；窗口已经关闭时直接清理本地记录。
4. 正常退出时执行全部恢复，恢复失败必须如实提示，不能宣称全部成功。

### 状态保存

置顶记录只保存在内存，包括窗口标识、所属进程、原始层级和用于列表展示的 App 名称。首版不写窗口标题数据库，不持久化用户工作内容。

## 6. 错误与边界

- **无权限**：展示权限说明、「打开系统设置」和「重新检查」。
- **快捷键冲突**：提示注册失败，菜单操作仍可使用，不静默忽略。
- **没有可置顶的当前窗口**：提示先切换到一个普通 App 窗口。
- **窗口已关闭**：从列表清理，不再调用恢复。
- **目标窗口进入不支持状态**：提示无法继续操作，不伪造成功。
- **私有符号缺失或调用失败**：显示当前 macOS 不受支持，并保留原始响应信息供排查。
- **App 异常退出**：首版不保证自动恢复已置顶窗口；README 说明可通过重开目标窗口或目标 App 恢复。
- **多个置顶窗口**：只保证高于普通窗口，不承诺它们之间的固定前后顺序。

## 7. 隐私与开源约束

- 不读取窗口正文，不申请屏幕录制权限。
- 辅助功能权限仅用于识别当前窗口。
- 无网络请求、无遥测、无第三方运行时依赖。
- 代码和图标自行编写，不使用 Apple Logo 作为 App 图标。
- 不复制第三方实现；以后若引入第三方代码，单独审查并保留许可证。
- 使用 MIT 许可证，README 明示私有 API、系统升级兼容风险、权限要求和异常退出限制。
- GitHub 公开仓库和推送属于单独发布动作，执行前必须再次取得用户确认。

## 8. 验证策略

### 8.1 可行性闸门

完整 App 开发前，先用最小程序在当前 macOS 上验证：

1. 能识别 Safari 当前标准窗口并取得正确窗口标识。
2. 能提高该窗口层级。
3. 切换到备忘录和 IDE 后，Safari 仍在普通窗口上方。
4. 能恢复原层级，而不是只能关闭窗口解决。
5. 私有符号缺失或失败时有可观察的错误结果。

任一关键项失败，就停止完整 App 实现并向用户报告，不改用截图浮窗冒充成功。

### 8.2 自动化测试

使用假的 Gateway 覆盖：

- 置顶成功后才更新状态。
- 重复置顶同一窗口不会重复计数。
- 单独取消和全部取消。
- 已关闭窗口清理。
- 权限不足、符号缺失和系统调用失败不改变原状态。
- 正常退出恢复所有仍存活的窗口。

### 8.3 真机验收

- Safari 置顶后切换到备忘录，Safari 仍可见。
- Safari 置顶后切换到 IDE，Safari 仍可见。
- 再按快捷键后恢复正常层级。
- 同时置顶两个不同 App 的窗口，二者都高于普通窗口。
- 关闭已置顶窗口后，菜单列表和数量正确清理。
- 撤销辅助功能权限后显示权限状态，恢复权限后可重新操作。
- 正常退出 App 后，本进程置顶的窗口全部恢复。
