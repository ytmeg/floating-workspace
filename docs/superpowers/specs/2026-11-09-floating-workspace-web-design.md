# 悬浮工作台网页模式设计

- 日期：2026-11-09
- 状态：内核、浏览编辑、存储安全和验收方向已由用户确认；用户以 `/goal 完成网页的开发` 授权继续
- 项目：悬浮工作台
- 范围：WKWebView 网页浏览、本地正文编辑、按 URL 保存和单次重放

## 1. 目标与边界

在现有悬浮工作台中启用网页模式，保留便签、空白、玻璃主题、置顶、快捷键、持久化和窗口恢复。

- 使用公开 `WKWebView`，不引入 CEF、Chromium、Electron 或第三方浏览器依赖。
- 网页修改只影响本地 DOM，不写回远程网站，不调用网站写入 API，不主动提交表单。
- 仅允许用户主动输入或点击的 `http`/`https` 导航，不开放任意本地文件读取。
- 不绕过证书校验，不伪造浏览器身份，不保存 Cookie、密码或表单输入值。
- 网页模式之外的功能和后续图片模式不在本次完成声明内。

## 2. 浏览与编辑体验

### 2.1 工具栏

- URL 输入框和「打开」按钮。
- 后退、前进、刷新。
- 「编辑正文」／「结束编辑」切换。
- 当前 URL、加载状态、保存状态和错误提示。

输入非法 URL 时不创建请求；加载失败、证书错误和导航被拒绝时显示具体原因。

### 2.2 本地正文编辑

- 进入编辑模式时，通过 `WKWebView.evaluateJavaScript` 设置 `document.body.contentEditable = "true"`。
- 用户直接编辑当前页面正文；退出编辑模式恢复 `contentEditable = "false"`。
- 编辑模式下拦截表单 `submit` 事件，防止本地编辑被当成远程提交。
- 不通过 AppleScript、注入其他浏览器或远程调试修改页面。

## 3. 草稿保存与重放

### 3.1 URL 规范化

草稿键使用 `URLComponents` 生成：

- scheme 和 host 转小写。
- 删除 fragment、用户名、密码和默认端口。
- 空 path 规范为 `/`；保留其余 path、query 和末尾斜杠，不假设它们等价。
- 含用户名或密码的 URL 拒绝保存，避免凭据进入草稿。

### 3.2 草稿内容

进入或保持编辑状态时，保存按钮和自动保存会使用页面内的 DOM 清理逻辑生成正文 HTML，而不是执行远程写入。自动保存采用停止输入 800ms 后的异步读取，避免每 300ms 序列化整页 DOM；结束编辑、导航离开和正常退出前必须尝试保存。

清理规则：

- 删除 `script`、`iframe`、`object`、`embed` 和 `meta[http-equiv=refresh]`。
- 删除所有 `on*` 事件属性、`javascript:` URL 和表单输入值。
- 删除表单 `action` 和 `method` 属性，并在编辑及重放后拦截 submit。
- 保留普通正文、链接、图片和文本结构，不追求原页面的脚本行为。

保存字段：

- `url`：规范化后的 URL。
- `sanitizedBodyHTML`：清理后的正文 HTML。
- `updatedAt`：本机保存时间。

### 3.3 单次重放

- 同一规范化 URL 加载完成后，如果存在草稿，在 `didFinish` 后尝试应用一次。
- 重放前再次执行清理，不把保存时的主动内容带回页面。
- 不循环重放，不与网站动态更新争夺 DOM。
- 页面结构变化导致重放失败时显示「无法应用上次修改」，保留草稿供用户查看或重新编辑，不静默删除。
- 重放成功后才显示「已恢复上次修改」。

## 4. 组件设计

### WebViewController

负责工具栏、WKWebView、编辑模式、导航代理、错误展示和重放状态。网页导航与编辑动作不直接修改 `WorkspaceContent`。

### WebDraftStore

负责按 URL 读取、保存、更新时间戳和重放描述。通过 `ContentStore` 的增量模型持久化，复用现有防抖和原子保存。

### WebDraftSanitizer

以页面 DOM 为边界执行清理，避免用正则表达式解析完整 HTML。清理函数独立、可测试，不访问网络或本地文件。

### WorkspaceContent 迁移

- 新模型版本为 `schemaVersion = 2`，增加 `webDrafts`。
- 读取版本 1 时保留全部便签、空白和置顶字段，补空 `webDrafts` 并迁移为版本 2。
- 读取版本 2 时直接解码；更高版本回退到现有损坏/不兼容错误路径，不静默重置。
- 首次迁移保存前保留原版本文件备份；后续正常保存使用现有原子写入。

## 5. 隐私与安全

- 浏览器使用 `WKWebsiteDataStore.nonPersistent()`，Cookie 和网站数据仅保留在当前进程会话。
- 不保存密码、表单输入值或网站凭据。
- 网络仅用于用户主动打开的网页及其正常资源加载。
- 草稿清理在保存和重放各执行一次，避免脚本、事件和表单提交随草稿恢复。
- 页面自身的脚本仍按 WKWebView 默认行为运行；本设计不承诺隔离所有恶意网页，用户应只打开可信来源。

## 6. 错误与回退

- **非法 URL**：输入框下显示原因，不发出请求。
- **网络/证书失败**：展示错误并保留当前正文，不覆盖草稿。
- **重放失败**：保留草稿和当前页面，提示无法应用，不自动重试。
- **保存失败**：沿用现有 dirty、失败状态和退出重试/明确放弃流程。
- **网页无 body**：返回无法编辑，不创建空草稿。
- **用户导航到其他 URL**：先保存当前草稿，再允许导航，避免未保存内容丢失。

## 7. 验证策略

### 自动化测试

- URL 规范化、凭据拒绝和 schema v1→v2 迁移。
- DOM 清理脚本、事件、表单值和主动元素。
- 编辑停顿 800ms 才序列化，连续输入不会每次触发整页读取。
- 编辑模式切换、导航前保存、单次重放和失败保留草稿。
- 非持久化网站数据存储配置。
- 现有全部测试和便签/空白/置顶回归。

### 真机验收

1. 打开静态测试网页，编辑正文，刷新后单次重放成功。
2. 动态页面结构改变后提示无法应用旧修改，不循环重放。
3. 非法 URL、网络失败和证书错误均有可见提示。
4. 保存草稿不包含脚本、事件属性、表单输入值或提交地址。
5. 导航到其他 URL 前保存当前草稿，返回后可恢复。
6. 浅色/深色主题下工具栏和正文可读，减少透明度回退正常。
7. 最终签名包重新通过原八组功能验收，无 Dock 图标、无额外权限请求。

## 8. 完成标准

只有自动化测试、草稿安全、重放失败处理、主题检查和原八组功能验收全部通过，才可声明网页模式完成。图片模式、登录状态持久化和远程网站写回不纳入本次完成声明。
